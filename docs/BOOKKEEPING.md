# 기장 · 경비 전표와 분개장

**기장**은 거래를 날짜·거래처·계정과목·금액으로 장부에 기록하는 업무입니다. 복식부기는 거래를 차변과 대변으로 나누어 기록합니다. [국세청 기장 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7664&mi=2226), [국세청 간편장부 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7670&mi=2231)를 참고했습니다.

앱의 **영수증 확정**은 OCR 내용과 업무 목적을 확인하는 단계이고, **전표 기장**은 확인한 거래를 회계 분개 형태로 기록하는 별도 단계입니다. 기존 확정 내역은 자동 기장하지 않습니다.

## 사용 순서

1. 영수증의 거래일·거래처·계정과목·적요·금액을 확인하고 **확정하여 장부에 반영**합니다.
2. 해당 영수증을 다시 열고 아래 **전표 기장** 영역에서 기장일·기장 담당자·대변 상대계정·전표 적요를 입력합니다. 저장하지 않은 수정 내용이 있으면 먼저 저장·확정해야 합니다.
3. 차변·대변 미리보기를 확인하고 **전표 기장**을 누릅니다.
4. **기장 · 분개장** 화면에서 전표번호, 기장일, 계정, 거래처, 금액, 담당자와 기장 상태를 확인합니다. 월 필터 기준은 영수증 거래일이 아닌 **기장일**입니다.
5. 기장한 영수증을 고치려면 담당자와 사유를 입력해 **기장 취소**한 뒤 수정·확정·재기장합니다. 이전 전표의 금액·상호·계정과 취소 이력은 유지되며 새 전표번호가 발급됩니다.

예를 들어 직원 점심 22,000원을 법인카드 미지급금으로 총액 비용 처리하면 다음과 같습니다.

| 구분 | 계정 | 금액 |
|---|---|---:|
| 차변 | 복리후생비 | 22,000원 |
| 대변 | 미지급금(법인카드) | 22,000원 |

이는 카드대금을 은행에서 실제 지급한 거래까지 기록한다는 뜻은 아닙니다. 결제수단에서 제안한 상대계정은 실제 지급 상태에 맞는지 확인해야 합니다.

## 부가세 처리

기본 방식은 **총액을 비용으로 기장**입니다. **부가세대급금 별도 계상**은 사용자가 공제 가능 여부를 검토하고 명시적으로 선택할 때만 적용합니다. 원본에서 확인한 공급가액과 부가세의 합계가 총액과 일치해야 합니다. OCR나 음식·도서 분류만으로 공제 가능 여부를 자동 결정하거나 세액을 계산하지 않습니다.

## 이력·중복·증빙 보존

기장된 영수증은 수정·회전·재인식·삭제를 차단합니다. 취소 후에는 수정할 수 있지만 기장 이력이 있는 영수증 자체는 삭제할 수 없습니다. 전표가 참조한 당시 증빙 사진은 이후 회전으로 교체되더라도 남겨 두며, 분개장 행의 **기장 당시 증빙**으로 확인합니다. 보존 파일을 포함해 앱 종료 후 `data` 폴더 전체를 백업하세요.

같은 영수증의 이중 기장은 DB의 유일성 제약과 행 잠금으로 막습니다. 기장·취소 시 영수증 버전을 올려 오래된 창의 변경 요청을 거절합니다. 담당자·시각·취소 사유를 기록하지만 입력한 담당자는 로그인 인증값이 아닙니다.

## 엑셀과 구글 스프레드시트

**분개장 엑셀**은 현재 기장 월·검색 조건으로 세 시트를 만듭니다.

- `분개장`: 완료 전표의 차변·대변 기록. 취소 전표는 제외합니다.
- `계정별발생`: 완료 전표의 계정별 차변·대변 발생 합계. 기초 잔액을 포함한 잔액이나 재무제표가 아닙니다.
- `기장취소이력`: 취소 전표 원본과 담당자·시각·사유. 활성 합계에서는 제외합니다.

화면의 전표 상태 필터는 엑셀에서 취소 이력을 숨기는 용도로 쓰지 않습니다. 기존 **엑셀 내보내기**와 **Google Sheets 직접 전송**은 영수증 확정 장부이므로 미기장 확정 건도 포함합니다. 분개장을 Google Sheets에서 보려면 별도 분개장 XLSX를 가져오세요.

## 적용 범위와 시작 방법

이 기능은 **영수증 지출의 기장 보조** 범위입니다. 매출·자산·차입금 등 전체 거래 입력, 카드대금·직원 경비 지급의 후속 거래, 기초 잔액, 기간 마감·역분개·결산, 전체 재무제표와 세무 신고는 포함하지 않습니다. 클라이언트의 실제 계정 체계·결제 흐름·세무사 전달 형식은 추가 확인이 필요합니다.

기존 H2 장부는 유지하며 첫 재시작 때 기장 전용 테이블과 인덱스를 추가합니다. IntelliJ에서 기존 앱을 종료하고 다시 실행한 뒤 브라우저를 새로고침하세요. 운영 DB를 교체하거나 별도 서버를 구매할 필요는 없습니다.

## 개발자가 읽을 코드

- `BookkeepingController`: 조회·기장·취소·증빙·엑셀 API
- `BookkeepingService`: 저장된 확정 영수증 검증, 분개 값 확정, 전표번호와 이력 관리
- `LedgerRepository`: 영수증 변경과 기장의 행 잠금 공유, 기장 증빙 보호
- `BookkeepingExporter`: 분개·발생 합계·취소 이력의 XLSX 출력
- `bookkeeping.js`: 기장 입력, 저장 전 변경 감지, 분개 미리보기, 상태·분개장 표시
- `BookkeepingWorkflowTest`, `BookkeepingMigrationTest`: 동시 기장, 취소·재기장, 증빙 보존, 기존 장부 유지 검증
