# 세금계산서 사진·PDF 등록

## 지원 기준과 사용 방법

종이 세금계산서의 법정 양식인 **부가가치세법 시행규칙 별지 제14호서식**을 기준으로 구현했습니다.
공급자/공급받는 자, 작성일, 공급가액/세액, 품목·규격·수량·단가·공급가액·세액, 합계금액을 구분합니다.
종이 일련번호와 전자세금계산서 승인번호는 세금계산서 번호에 저장하며 카드 승인번호와 혼용하지 않습니다.

1. 상단 **세금계산서 등록** 탭을 선택한 뒤 JPG·PNG 사진 또는 PDF를 파일 선택/끌어 놓기로 등록합니다. 영수증은 **영수증 등록** 탭을 사용합니다.
2. **한 사진·한 페이지에 세금계산서 한 장**을 넣습니다. 공급자용/공급받는 자용 두 사본이 함께 있는 페이지도 한 장씩 잘라 주세요. 두 사본을 더해 집계하지 않습니다.
3. 위 거래처·사업자번호·주소가 **공급자**인지 확인합니다. 별도 세금계산서 패널의 공급받는 자는 실제 매입 회사와 대조합니다.
4. 품목별 단가·수량·공급가액·세액을 대조하고 누락은 직접 수정합니다. 제목 인식이 실패해도 세금계산서 전용 폼이 유지됩니다. 사진 없이 입력하려면 세금계산서 탭을 선택하고 **세금계산서 직접 입력**을 누릅니다.
5. 업무 목적(적요)과 계정과목, 문서 합계를 확인한 뒤 저장·확정합니다. 공급가액/세액의 품목 합계가 모두 입력되었는데 문서 합계와 다르면 확정이 차단됩니다.
6. 확정 자료를 엑셀로 내보냅니다. 세금계산서가 포함된 경우에만 `세금계산서품목` 시트가 추가됩니다.

사진은 10MB, PDF는 25MB·20페이지까지 지원합니다. XML·XLSX·HWP·메일 HTML 원본 가져오기는 이번 범위에 포함하지 않습니다. 인쇄 가능한 파일은 PDF로 저장해 등록할 수 있습니다.

## 인식·검증 방법

- 텍스트가 포함된 세금계산서 PDF는 PDFBox로 원래 글자와 위치를 읽습니다. 사진·스캔 PDF는 Windows OCR를 사용합니다. 일반 영수증 PDF는 기존 OCR 흐름을 유지합니다.
- 두 사업자 정보는 좌우 좌표로 나누며, 위치가 없는 텍스트는 명시적인 공급자/공급받는 자 구역만 읽습니다. 모호하면 공급자 번호를 비워 두며 매입자 번호로 대신하지 않습니다.
- 품목의 열 제목과 좌표를 연결하며, 수량·단가는 소수점도 보관합니다. 공급가액·세액은 원 단위입니다. 표 구획이나 글자가 흐리면 일부 값은 비워 둡니다.
- 총금액이 없고 문서의 공급가액·세액이 명시되어 있으면 두 값의 합을 총금액으로 제안하며 안내를 남깁니다. 반대로 총금액이나 수량×단가로 누락 공급가액·부가세를 역산하지 않습니다.
- 수정/음수 세금계산서, 여러 문서가 담긴 페이지, 손글씨·비뚤어진 표·자리수 칸의 오독 등은 원본 검토가 필요합니다. 일반 양수 지출 장부에서 음수 수정분을 자동 상계하지 않습니다.
- 인식은 제안이며 전자서명, 실제 발급·국세청 전송 여부, 회사 소유의 매입 증빙인지 검증하는 기능은 아닙니다. 텍스트층과 보이는 PDF 원본도 대조해야 합니다.
- 기장 시 품목도 사본으로 보관합니다. 취소 후 원본 품목을 수정해도 과거 전표의 사본은 바뀌지 않습니다. 기장 엑셀의 품목 시트에는 취소 여부를 명시합니다.
- 기존 저장 자료는 자동 변경하지 않습니다. 앱 재시작 후 ‘사진 다시 읽기’ 또는 직접 입력을 사용하세요. 품목 수정 중에는 먼저 저장해야 재인식·국세청 조회·기장을 진행할 수 있습니다.

## 엑셀·공제 검토

지출장부/Google Sheets의 기존 A~W 열 뒤에 X `증빙종류`, Y `세금계산서번호`, Z `공급받는자사업자번호`, AA `공급받는자상호`를 추가했습니다. **거래처주소는 마지막 AB열**입니다. 품목 상세 시트는 XLSX 내보내기에서 제공하며 Google Sheets 직접 전송은 문서 요약만 전송합니다.

단가는 한 단위의 가격, 공급가액은 부가세를 제외한 거래 대가, 세액은 명시된 부가세입니다. 단가·공급가액 전액을 부가세로 공제하는 것은 아닙니다. 세금계산서여도 업무 목적·매입자·불공제 사유·신고 요건을 확인해야 하며, 공제 후보는 환급 확정이 아닙니다. 이번 기능은 기존 공제 검토를 유지하고 공급받는 자 번호·품목 합계 확인을 추가합니다.

## 개발자 참고

`TaxInvoiceParser`가 문서 종류·표를 판별하고 `PdfPageText`가 PDF 좌표를 추출합니다. `TaxInvoice`와 `TaxInvoice.Item`은 `tax_invoice_json` CLOB에 저장합니다. DB 열은 추가 방식으로 반영하여 기존 영수증을 보존합니다. `invoices.js`가 검토 화면, `TaxInvoiceWorkbook`이 품목 시트, 기장 서비스가 당시 사본을 담당합니다.

## 영수증과 전용 폼 분리

- 영수증 검토는 기존 항목·순서를 유지하며 세금계산서 전용 항목을 표시하지 않습니다.
- 세금계산서는 공급자 → 공급받는 자 → 작성일·문서 번호 → 품목 → 문서 합계 → 업무 목적·계정과목 → 사업자 조회·공제 검토 순서로 표시합니다. 거래 시간·카드 승인번호는 이 폼에서 숨깁니다.
- 업로드 시작 시 선택한 종류를 서버로 전달합니다. 세금계산서 제목을 읽지 못해도 선택 종류를 유지하며, 재인식도 저장된 종류를 사용합니다. 기존 클라이언트의 종류 없는 요청은 자동 판별을 유지합니다.
- 문서 종류는 기존 `tax_invoice_json` 부가 정보로 구분하므로 기존 DB를 다시 분류하지 않습니다.
- 전체 장부에서 종류 배지로 구분하고 **증빙 종류** 필터를 목록과 엑셀에 함께 적용합니다. 중복 검토는 종류와 무관하게 전체 자료를 비교합니다. 같은 파일을 다른 탭에 올려도 새로 등록하거나 기존 종류를 자동 변경하지 않습니다.
- API의 사진 업로드는 `documentType=RECEIPT|TAX_INVOICE`, PDF 페이지 등록은 JSON의 `documentType`, 직접 입력은 `/api/expenses?documentType=...`를 사용합니다. 목록과 엑셀도 같은 쿼리로 필터링합니다.
